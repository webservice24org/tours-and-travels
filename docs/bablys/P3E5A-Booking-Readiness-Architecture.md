# P3E.5A — Booking Readiness and Seat Ledger Architecture

## Boundary

This package adds **trusted internal** readiness assessment and staff-authorized seat commitments. It does NOT expose public booking APIs or allow customers to reserve seats. All public booking UI, identity validation, contact information, price snapshots, payments, expiry, refunds, customer messaging and email dispatch are outside this scope.

The distinction matters: an `open` departure from P3E.4A and an `eligible_for_internal_allocation` readiness snapshot do **not** imply that the customer can book online; `public_bookable` remains false.

## Domain prerequisites

`TourBookingReadiness::inspect(tour, departure, variantCode, adults, children, at)` checks, with no writes:

1. At least one adult; total group from 1 through 1000.
2. Tour not soft-deleted, status published, and `published_at <= at`.
3. At least one currently published category and destination.
4. Departure belongs to tour and has status `open`.
5. Departure has not started and `booking_closes_at` (if present) has not passed.
6. At least requested seats available from `capacity_total - seats_committed`.
7. Matching active pricing variant in the same tour, valid adult/child or group rules, traveler limits, and a server-calculated quote (P3E.3A).

Readiness contains reason codes for internal UI/diagnostics; no customer-facing HTTP route is installed.

## Atomic seat mutation protocol

`TourSeatAllocationManager::commit(staffActor, tour, departure, opaqueReference, priceVariantCode, adults, children)`:

- Validates the opaque idempotency key.
- Begins a DB transaction and checks `tours.edit` + `tours.publish` for the actor.
- Locks the **tour** row, as all departure changes and future booking writes must.
- Looks up existing reference under a lock; exact committed retry returns the original record without changing capacity/audit. Reused/changed/released references fail.
- Locks the **departure** row and validates its parent. Rechecks all readiness rules **inside the same transaction** using server current UTC time.
- Executes a guarded atomic SQL increment with predicate `seats_committed <= capacity_total - requested_seats`.
- Inserts the ledger record with its global unique reference; any insert/ audit failure rolls back the counter change.
- Writes a redacted audit event `tour.seats.committed` containing only the allocation ID.

`release(staffActor, tour, opaqueReference)`:

- Locks parent tour and allocation. If already released, returns false without a mutation.
- Locks departure and performs guarded atomic decrement (`seats_committed >= allocated_seats`).
- Marks the ledger released and writes an audit `tour.seats.released` in the same transaction.
- Release is permitted after a departure is closed, cancelled or past its cutoff, to support future cancellations and operational corrections.

**Critical concurrency note:** This package provides database row locks and conditional updates but no multi-connection integration harness. SQLite does not model MySQL row-level contention. Validate on disposable MySQL with two concurrent connections before enabling public bookings; expect only one commit when both requests compete for the last seats.

## Idempotency and lifecycle

- The `reference_key` is a globally unique, 8–100 character ASCII opaque reference generated by a trusted booking workflow, never a name, email or phone number.
- `committed` and `released` are the only ledger states here. This is **not** a temporary hold/expiry lifecycle.
- A released row is retained as an idempotency tombstone. `departure_id` is `NULL ON DELETE`, so the reference survives an eventual departure deletion while preserving tour ID and departure code.
- Tour hard deletion cascades ledger rows. Preserve audit archives and legal retention rules when a destructive operation is later introduced.
- The existing P3E.4A `TourDepartureManager` prevents departure deletion and date edits while `seats_committed > 0`. If all seats have been released, removal is permitted; ledger tombstones remain.
- Direct manual DB writes to `seats_committed` can desynchronize the ledger. The future booking adapter must use this service only, not direct SQL mutations outside it.
- No price is frozen in the ledger. The future booking model must snapshot currency, variant, unit and total minor-unit amounts at transaction time to preserve contractual pricing.

## No application/route changes

This package doesn't touch Laravel routes, the native `AppSidebar`, editor files, RBAC role definitions or existing service classes. This prevents regressions in the locally verified P3E.4B/P3E.3B/P3E.2 editor.

## Follow-on P3E.5B

- Booking aggregate/status machine: initiated, pending, confirmed, cancelled, expired (and strict transitions).
- Customer identity and contact details with privacy/consent handling.
- Quote/price/currency snapshots, tax/fee policy and provider/payout policies.
- Expiring holds with a worker, or a deliberately non-expiring commitment workflow. Define this before exposing booking buttons.
- Authorization by customer or guest, rate limiting, CSRF/session validation, anti-replay/idempotency keys.
- Live MySQL concurrency and crash/retry acceptance tests.
- Customer booking page and administrator booking operations using the unified native sidebar, shared ConfirmDialog and toast.
- Public bookability should remain false until these are complete and explicitly accepted.
